# 1. Docker Compose

## 핵심 개념

> 여러 컨테이너로 구성된 애플리케이션을 YAML 형식의 파일로 명확하게 정의하고, 단일 명령어로 동시에 실행·관리할 수 있도록 지원하는 Docker의 공식 오픈소스 도구
> 

## 나온 이유 — Docker 명령어로만 구성했을 때의 어려움

여러 서비스를 실행하거나, 네트워크를 만들거나, 볼륨을 설정할 때 명령어를 일일이 직접 쳐야 했다.

```bash
docker network create app-network
docker volume create mysql-data

docker run -d --name mysql --network app-network \
  -e MYSQL_ROOT_PASSWORD=password -e MYSQL_DATABASE=demo \
  -v mysql-data:/var/lib/mysql mysql:8.0

docker run -d --name backend --network app-network \
  -e DB_HOST=mysql -e DB_PORT=3306 -p 8080:8080 my-backend:1.0.0

docker run -d --name nginx --network app-network -p 80:80 \
  -v $(pwd)/nginx.conf:/etc/nginx/conf.d/default.conf:ro nginx:stable-alpine
```

처음엔 실행할 수 있지만 다음 상황에서 무너진다.

| 상황 | 문제 |
| --- | --- |
| 서비스가 늘어남 | 명령어가 계속 많아짐 |
| 운영 중 수시로 껐다 켜야 함 | 옵션 추가 시마다 명령어 수정 필요 |
| 다른 개발자가 실행해야 함 | 긴 명령어를 그대로 공유·재현해야 함 |
| 실행 순서 | 백엔드는 DB가 준비된 뒤 떠야 하는데, DB 컨테이너 생성이 더 오래 걸림 |

## Docker Compose에서는

> 컨테이너 여러 개를 하나의 애플리케이션으로 관리하기 어려우니, 그걸 해결한다.
> 

애플리케이션 구성을 Compose 파일에 적어두고 사용한다.

```
애플리케이션 구성
├── 어떤 이미지로 실행할지
├── 어떤 Dockerfile로 빌드할지
├── 어떤 포트를 열지
├── 어떤 환경 변수를 넣을지
├── 어떤 네트워크에 연결할지
├── 어떤 볼륨을 연결할지
├── 어떤 서비스에 의존하는지
└── 장애 시 재시작할지
```

# 2. Docker Compose의 핵심 개념

## Project(Stack)

프로젝트 구성 예시:

```
memo-app/
├── compose.yaml
├── backend/  └── Dockerfile
├── frontend/ └── Dockerfile
└── nginx/    └── default.conf
```

`docker compose up -d`로 실행 후 `docker ps`를 보면, 프로젝트명(`memo-app`)을 접두어로 리소스가 생성된다.

```
memo-app-backend-1
memo-app-mysql-1
memo-app-nginx-1
memo-app_default        # 네트워크
memo-app_mysql-data     # 볼륨
```

→ `memo-app` 전체가 하나의 Stack(Project).

## Service

> Docker Compose에서 Service는 "실행해야 하는 컨테이너의 역할"이다.
> 

```yaml
services:
  backend:
    image: my-backend:1.0.0
  mysql:
    image: mysql:8.0
  nginx:
    image: nginx:stable-alpine
```

- `backend`, `mysql`, `nginx`는 컨테이너 이름이 아니라 **애플리케이션 내부에서 사용하는 논리적 역할 이름**이다.
- 백엔드가 DB 주소를 바라볼 때 IP 대신 서비스 이름을 쓸 수 있다.
    
    ```bash
    DB_HOST: 172.~~   # ❌ IP 직접 지정DB_HOST: mysql    # ✅ 서비스 이름
    ```
    
- 서비스는 논리적 역할이므로 **스케일 아웃**이 가능하다.
    
    ```bash
    docker compose up -d --scale backend=3# memo-app-backend-1 / -2 / -3
    ```
    
    - 이때 `container_name`을 지정하면 식별자가 고정되어 스케일과 충돌한다.
    - 스케일이 필요하면 `ports`(`8080:8080`) 같은 호스트 포트 공개도 하면 안 된다(포트 충돌).

## Network

Compose를 사용하면 별도로 네트워크를 만들지 않아도 **기본 네트워크가 자동 생성**된다. 같은 네트워크 안의 서비스끼리는 서비스 이름으로 통신할 수 있다.

```yaml
services:
  backend:
    image: my-backend:1.0.0
  mysql:
    image: mysql:8.0
  nginx:
    image: nginx:sts
```

## Volume

컨테이너가 삭제되면 내부 데이터가 사라지므로, 볼륨으로 호스트 저장소를 사용한다.

```yaml
services:
  mysql:
    image: mysql:8.0
    volumes:
      - mysql-data:/var/lib/mysql

volumes:
  mysql-data:
```

## 환경 변수(environment)

컨테이너마다 다른 값을 넣거나, 추가·변경되는 값을 관리한다. (`docker run -e ...`를 파일로 옮긴 것)

```yaml
services:
  backend:
    image: my-backend:1.0.0
    environment:
      SPRING_PROFILES_ACTIVE: prod
      DB_HOST: mysql
      DB_PORT: 3306
      DB_PASSWORD: 0123456789a
```

**단, API Key·비밀번호는 yaml에 직접 적지 않는다.** `docker-compose.yaml`은 깃허브로 공유되는 파일이기 때문. `${...}`로 참조하고 실제 값은 `.env`나 Secret 관리 서비스에 둔다.

```yaml
services:
  mysql:
    image: mysql:8.0
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
      MYSQL_DATABASE: ${MYSQL_DATABASE}
```

```bash
# .env
MYSQL_ROOT_PASSWORD=실제비밀번호
MYSQL_DATABASE=memo
```

## depends_on

서비스 간 생성·시작 순서(의존성)를 선언한다.

```yaml
services:
  backend:
    image: my-backend:1.0.0
    depends_on:
      - mysql
  mysql:
    image: mysql:8.0
```

- **주의: 컨테이너의 생성·시작 순서만 조정할 뿐, 내부 프로세스가 실제 요청을 받을 준비가 됐는지는 보장하지 않는다.** (컨테이너 실행 순서 ≠ 프로세스 준비 순서)
- 준비 완료까지 보장하려면 `healthcheck` + `condition: service_healthy`를 함께 쓴다.

```yaml
services:
  backend:
    image: my-backend:1.0.0
    depends_on:
      mysql:
        condition: service_healthy
  mysql:
    image: mysql:8.0
    environment:
      MYSQL_DATABASE: memo
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
    healthcheck:
      test: ["CMD-SHELL", "mysqladmin ping -h localhost -p$$MYSQL_ROOT_PASSWORD"]
      interval: 10s
      timeout: 5s
      retries: 10
```

# 3. 실무 예시 — Nginx + WAS + DB

> 도커 컨테이너를 단독으로 쓰는 경우는 드물다. 환경 변수·명령어가 필요해 대부분 Compose로 실행한다.
> 

```yaml
services:
  nginx:
    image: nginx:stable-alpine
    ports:
      - "80:80"
    volumes:
      - ./nginx/default.conf:/etc/nginx/conf.d/default.conf:ro
    depends_on:
      - backend
    restart: unless-stopped
    networks:
      - frontend

  backend:
    image: your-dockerhub-username/memo-backend:1.0.0
    environment:
      SPRING_PROFILES_ACTIVE: prod
      DB_HOST: mysql
      DB_PORT: 3306
      DB_NAME: memo
      DB_USERNAME: root
      DB_PASSWORD: ${MYSQL_ROOT_PASSWORD}
    depends_on:
      mysql:
        condition: service_healthy
    restart: unless-stopped
    networks:
      - frontend
      - backend

  mysql:
    image: mysql:8.4.0
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
      MYSQL_DATABASE: memo
    volumes:
      - mysql-data:/var/lib/mysql
    healthcheck:
      test: ["CMD-SHELL", "mysqladmin ping -h localhost -p$$MYSQL_ROOT_PASSWORD"]
      interval: 10s
      timeout: 5s
      retries: 10
    restart: unless-stopped
    networks:
      - backend

networks:
  frontend:
  backend:

volumes:
  mysql-data:
```

## 어디서 많이 쓰나 — 특히 개발 서버

| 환경 | 구성 방식 |
| --- | --- |
| 운영 서버 | 보통 컨테이너들이 분리 구성 (BE EC2 → BE Container, FE EC2 → FE Container). 사이드카 패턴, 복제본 개수 조정 등 |
| 개발 서버 | 하나의 서버(EC2)에 여러 컨테이너를 함께 둠. 개발자가 본인 기능을 테스트하는 게 주 목적 |
| 로컬 | 로컬 개발 환경 통일 |

# 4. 주의해야 하는 사항

| # | 원칙 | 이유 / 대응 |
| --- | --- | --- |
| 1 | `latest` 태그를 피한다 | `image: kiwinam/memo-app:latest`는 편하지만 실제 배포 버전을 알 수 없음. `1.1.0` 같은 버전 태그나 이미지 빌드 시 생성되는 SHA 태그(깃 커밋 SHA 등)를 명시 |
| 2 | `depends_on`을 신뢰하지 않는다 | 순서만 조정할 뿐 준비 완료를 보장하지 않음. 의존성이 꼭 필요하면 `healthcheck`를 함께 사용 |
| 3 | 로그 회전(rotation)을 설정한다 | 기본 도커 로그는 서버 디스크에 계속 쌓임. 운영에서는 크기·개수 제한으로 회전시켜야 함 |

**로그 회전 설정 예시**

```yaml
services:
  backend:
    image: my-company/backend:1.0.0
    logging:
      driver: json-file
      options:
        max-size: "10m"
        max-file: "5"
```

# 5. 전체 정리

| 개념 | 핵심 |
| --- | --- |
| Docker Compose | 여러 컨테이너 애플리케이션을 YAML로 정의하고 단일 명령어로 함께 실행·관리하는 공식 도구 |
| Project(Stack) | Compose로 묶인 전체 애플리케이션 단위. 프로젝트명이 리소스 접두어가 됨 |
| Service | 실행할 컨테이너의 논리적 역할 이름. 서비스 이름으로 내부 통신·스케일 가능 |
| Network | 자동 생성되는 기본 네트워크. 같은 네트워크면 서비스 이름으로 통신 |
| Volume | 컨테이너 삭제 시 데이터 유실 방지를 위해 호스트 저장소 연결 |
| environment | 컨테이너별 환경 변수. 비밀 값은 `${...}` + `.env`/Secret으로 분리 |
| depends_on | 시작 순서만 조정(준비 완료 보장 X) → `healthcheck` 병행 |
