## 1. 운영체제 (Operating System)

> 하드웨어와 소프트웨어를 관리하며, 사용자와 컴퓨터 간 상호작용을 가능하게 하는 시스템 소프트웨어
> 

사용자가 실행하는 프로그램(자바, 브라우저, 메모장 등)은 CPU, 메모리, 디스크 같은 하드웨어 자원을 직접 제어하지 않는다. 사용자가 직접 하드웨어를 제어하려 하면 충돌과 오류가 발생하기 때문에, 운영체제가 그 사이에서 중재 역할을 한다.

| 역할 | 설명 |
| --- | --- |
| 자원 관리 | CPU, 메모리, 디스크 등의 하드웨어 자원을 효율적으로 분배하여 여러 프로그램이 충돌 없이 실행되도록 한다 |
| 사용자 편의성 | 복잡한 하드웨어 동작을 추상화하여 GUI/CLI 인터페이스로 쉽게 사용할 수 있게 한다 |
| 멀티태스킹 | 여러 작업을 동시에 실행하거나 조율하여 작업 간 간섭을 방지한다 |
| 보안 및 안정성 | 데이터와 시스템을 보호하고, 오류 발생 시 복구 절차를 통해 안정적인 운영을 보장한다 |

## 2. 리눅스 (Linux)

> 오픈소스 기반의 운영체제로, 서버·클라우드 환경에서 가장 널리 사용된다
> 

서버 엔지니어가 리눅스를 선택하는 주요 이유는 다음과 같다.

- **오픈소스**: 누구나 무료로 사용하고 내부 소스를 수정할 수 있다. 기업 요구에 맞게 커스터마이징이 가능하다 (예: 칼리 리눅스).
- **생태계**: 전 세계적으로 방대한 커뮤니티와 도구가 갖춰져 있다.
- **안정성**: 서버는 24시간 365일 중단 없이 동작해야 하므로, 안정성이 높은 리눅스가 적합하다.
- **자원 효율**: GUI 대신 CLI를 사용하므로 RAM·CPU 자원 소모가 적다. 서버 자원은 비용과 직결되기 때문에 이 차이가 크다.
- **자동화**: CLI 명령어는 텍스트 기반이기 때문에 스크립트(코드)로 작성해 수백 대의 서버를 일괄 제어할 수 있다.

## 3. 커널 (Kernel)

> 운영체제의 핵심으로, 하드웨어를 관리하고 하드웨어와 프로그램 사이에서 중재자 역할을 한다
> 

프로그램이 하드웨어에 직접 접근하면 충돌이나 데이터 손상 같은 위험이 생긴다. 커널은 이를 통제하기 위해 존재한다.

### 유저 모드 vs 커널 모드

운영체제는 실행 환경을 두 가지 모드로 나눠 **권한을 분리**한다.

| 구분 | 설명 |
| --- | --- |
| **유저 모드** | 일반 애플리케이션(자바, 브라우저 등)이 실행되는 공간. 하드웨어에 직접 접근할 수 없다 |
| **커널 모드** | 운영체제의 핵심 기능(파일 I/O, 메모리 쓰기, 네트워크 전송 등)이 실행되는 공간. 하드웨어 접근이 허용된다 |

유저 모드에서 하드웨어 자원이 필요할 때는 반드시 **시스템 콜**을 통해 커널에 요청해야 한다.

---

## 4. 시스템 콜 (System Call)

> 유저 모드의 프로그램이 운영체제 커널의 기능을 요청하는 공식 인터페이스
> 

하드웨어 자원(파일, 메모리, 네트워크 등)에 접근하려면 프로그램이 직접 처리할 수 없고, 반드시 커널에게 요청해야 한다. 시스템 콜은 그 요청 창구다.

**동작 흐름 예시 (`FileReader.read()`)**

```
1. 유저 모드 (자바 프로그램)
   └─ read() 메서드 호출 → OS에 파일 읽기 요청

2. JVM → OS 커널에 요청 전달
   └─ JVM 내부에서 C 언어의 read() 함수 → 리눅스 시스템 콜 호출

3. 커널 모드 전환
   └─ 시스템 콜 인터럽트 발생 → 커널이 디스크에서 파일 데이터 읽기

4. 결과 반환
   └─ 읽은 데이터를 JVM에 전달 → CPU가 유저 모드로 복귀
```

## 5. 메모리 구조

> 프로그램이 빠르고 안정적으로 실행될 수 있도록 RAM을 4가지 영역으로 나눠 관리하는 방식
> 

| 영역 | 설명 |
| --- | --- |
| **코드(Code)** | 실행할 프로그램의 명령어(기계어)가 저장된다. 읽기 전용으로 보호된다 |
| **데이터(Data)** | 전역 변수, static 변수처럼 프로그램 시작부터 종료까지 유지되는 데이터가 저장된다 |
| **힙(Heap)** | 런타임에 동적으로 할당·해제되는 메모리 공간. 실행 전에 크기를 알 수 없는 데이터(예: 파일 내용)에 사용된다 |
| **스택(Stack)** | 함수 호출 시 생성되는 지역 변수, 매개변수, 반환 주소 등이 저장된다. 함수가 종료되면 자동으로 해제된다 |

**4개로 나누는 이유**

- 안정성: 코드 영역은 실수로 덮어쓰지 않도록 보호
- 효율성: 프로그램 종료까지 유지할 데이터와 즉시 버릴 데이터를 분리해 관리
- 유연성: 실행 중에 크기가 결정되는 데이터를 힙에서 유연하게 처리

## 6. 메모리 관리자 (Memory Manager)

> 시스템의 메모리를 관리하여 프로세스 간 자원 할당과 데이터 흐름을 최적화하는 소프트웨어 컴포넌트
> 

CPU(셰프)는 실제 연산을 담당하고, 디스크(냉장고)에 데이터가 저장되어 있으며, 메모리(작업대)는 CPU가 빠르게 접근할 수 있도록 데이터를 올려두는 공간이다. CPU와 디스크 간의 속도 차이를 메모리가 완충한다.

**메모리 관리자가 필요한 이유**

- 메모리는 비싸고 용량이 한정적이므로 낭비 없이 최대한 활용해야 한다
- 여러 프로세스가 서로의 메모리 공간을 침범하지 않도록 보호해야 한다
- 물리 메모리의 한계를 가상 메모리로 극복한다

---

## 7. 메모리 주소 체계

> CPU가 메모리의 특정 위치에 접근하기 위한 고유 주소 체계
> 

메모리를 1바이트 단위로 나누고 각 위치에 고유한 주소를 부여하여 관리한다.

| 구분 | 설명 |
| --- | --- |
| **논리 주소 (가상 주소)** | 프로그램이 바라보는 가상의 주소. 자바에서 객체 주소를 출력하면 이 논리 주소가 나온다. 각 프로그램은 자신이 0번지부터 메모리를 독점하고 있다고 생각한다 |
| **물리 주소** | RAM에 실제로 존재하는 하드웨어 주소 |
| **MMU (메모리 관리 장치)** | CPU가 논리 주소로 요청하면, MMU가 이를 실제 물리 주소로 변환하여 데이터를 가져온다 |

---

## 8. 메모리 관리 기법

### 메모리 오버레이 (Memory Overlay)

제한된 메모리 환경에서 프로그램을 여러 모듈로 쪼개고, 현재 필요한 모듈만 메모리에 올려 실행하는 기법. 개발자가 직접 모듈을 나눠야 했기 때문에 개발 난이도가 매우 높았고, 현재는 거의 사용하지 않는다.

### 메모리 스왑 (Memory Swap)

메모리가 부족할 때, 현재 사용하지 않는 데이터를 디스크의 스왑 공간으로 이동시켜 RAM을 확보하고, 필요할 때 다시 메모리로 불러오는 기법. 메모리 부족 문제를 해결할 수 있지만 디스크 I/O가 발생해 속도가 현저히 느려진다는 단점이 있다.

## 9. 메모리 관리 단위 (분할 방식)

여러 프로세스가 한정된 메모리를 충돌 없이 나눠 쓰기 위해 메모리를 특정 단위로 쪼개 관리한다.

### 고정 분할 (Fixed Partition)

메모리를 미리 고정된 크기의 블록으로 나누고, 각 블록에 프로세스를 하나씩 할당하는 방식.

- 장점: 관리가 단순하고 할당 속도가 빠르다
- 단점: **내부 단편화** 발생 — 프로세스 크기가 블록보다 작으면 블록 내 남은 공간이 낭비된다
- 주로 임베디드 시스템에서 사용

### 가변 분할 (Variable Partition)

프로세스의 실제 크기에 딱 맞춰 메모리를 동적으로 할당하는 방식.

- 장점: 메모리 활용이 효율적이다
- 단점: **외부 단편화** 발생 — 프로세스들이 들어왔다 나가길 반복하면 메모리 중간중간에 작은 빈 공간이 생겨, 전체 여유 공간은 충분해도 연속된 공간이 없어 새 프로세스를 할당하지 못하는 상황이 발생한다

### 페이징 (Paging)

메모리와 프로그램을 동일한 고정 크기(일반적으로 4KB)의 단위인 **페이지(프로그램)** 와 **프레임(메모리)** 으로 나눠, 연속되지 않은 물리 메모리 공간에도 자유롭게 배치하는 방식.

- 장점: 외부 단편화를 해결한다. 메모리를 연속으로 비워둘 필요가 없다
- 단점: 논리↔물리 주소 변환을 위한 **페이지 테이블**이 메모리를 추가로 사용하며, 주소 변환에 시간이 걸린다

### 세그멘테이션 (Segmentation)

프로그램을 코드·데이터·힙·스택 같은 **논리적 의미 단위(세그먼트)** 로 나눠 연속된 메모리 공간에 저장하는 방식.

- 장점: 프로그램의 논리 구조를 그대로 반영하므로 보호와 공유가 편리하다
- 단점: 세그먼트 크기가 제각각이라 외부 단편화가 발생할 수 있다

### 현대 OS: 페이징 + 세그멘테이션 혼합

프로그램을 먼저 세그멘테이션으로 논리 단위로 분리한 뒤, 다시 페이징으로 고정 크기 페이지로 나눠 관리한다. 두 방식의 장점을 모두 취하는 방법으로 현대 리눅스 등 대부분의 OS에서 사용한다.

## 10. 내부 단편화 vs 외부 단편화

| 구분 | 설명 | 발생 원인 |
| --- | --- | --- |
| **내부 단편화** | 할당된 메모리 블록 내부에 사용되지 않고 남는 공간 | 고정 분할 방식에서 프로세스 크기 < 블록 크기일 때 |
| **외부 단편화** | 전체 여유 공간은 충분하지만 연속된 공간이 없어 할당이 불가능한 상황 | 가변 분할·세그멘테이션에서 프로세스가 반복적으로 올라갔다 내려올 때 |

## 11. 가상 메모리 (Virtual Memory)

> 물리 RAM보다 큰 프로그램을 실행하고, 여러 프로세스를 안전하게 동시에 실행하기 위한 추상화 개념
> 

각 프로세스에게 마치 전체 메모리를 혼자 사용하는 것처럼 독립된 가상 주소 공간을 제공한다. 페이징과 세그멘테이션은 이 가상 메모리를 실현하기 위한 구체적인 기법이다.

> 가상 메모리 = 목표(배달 서비스 개념) / 페이징 = 구체적 실현 방법(오토바이 배달)
>

## 12. 프로세스 (Process)

> 운영체제로부터 자원을 할당받아 독립적으로 실행되는 하나의 프로그램 실행 단위
> 
- 독립된 메모리 공간(코드·데이터·힙·스택)을 가진다
- 운영체제가 멀티태스킹을 어떻게 수행하는지 이해하는 핵심 개념이다

---

## 13. 스레드 (Thread)

> 프로세스 내에서 병렬 처리를 위해 생성되는 실행 흐름의 최소 단위
> 
- 같은 프로세스 내 스레드들은 코드·데이터·힙 영역을 공유하고, 스택만 각자 따로 가진다
- 동시성과 병렬성을 활용해 프로그램의 실행 속도와 반응성을 높인다

| 특성 | 설명 |
| --- | --- |
| 멀티스레드 (Java Spring) | 요청마다 스레드를 생성하여 처리. 대규모 트래픽 처리에 적합하지만 스레드 관리 비용이 든다 |
| 싱글스레드 (Node.js) | 이벤트 루프 기반으로 적은 리소스로 높은 동시 처리량을 목표로 한다 |

---

## 14. IPC (Inter-Process Communication)

> 운영체제가 프로세스 간 데이터 교환을 위해 제공하는 통신 메커니즘
> 

프로세스는 기본적으로 독립된 메모리 공간을 가지므로 다른 프로세스의 메모리에 직접 접근할 수 없다. 프로세스 간 데이터를 주고받아야 하는 상황이 생기기 때문에 운영체제가 IPC를 제공한다.

| 방식 | 설명 | 특징 |
| --- | --- | --- |
| 원격 프로시저 호출 | 한 프로세스에서 다른 프로세스(심지어 다른 호스트)에 있는 함수를 로컬 함수처럼 호출하여 데이터를 교환하는 기술 | 고수준 API 제공, 개발이 간편하지만 성능 오버헤드 존재. |
| **공유 메모리** | 여러 프로세스가 공유하는 메모리 공간을 만들어 직접 데이터를 읽고 쓰는 방식 | 속도가 빠르지만 동시 접근 문제가 생길 수 있어 동기화(Synchronization)가 반드시 필요하다 |
| **파이프(Pipe)** | 단방향 데이터 스트림으로 부모-자식 프로세스 간 통신에 주로 사용된다 | 단방향이며 구조가 단순하다 |
| **소켓(Socket)** | 네트워크를 통한 프로세스 간 통신. 같은 머신이나 다른 머신의 프로세스와도 통신 가능하다 | 분산 시스템, 서버-클라이언트 구조에 활용된다 |

## 15. PCB (Process Control Block)

> 운영체제가 각 프로세스를 관리하기 위해 사용하는 데이터 구조
> 

CPU는 여러 프로세스를 빠르게 번갈아가며 실행하는데, 각 프로세스가 어디까지 실행했는지 기억하지 못하면 재개가 불가능하다. PCB는 이 정보를 저장하여 중단된 곳부터 이어서 실행할 수 있게 한다.

**PCB에 저장되는 정보**

| 정보 | 설명 |
| --- | --- |
| 프로세스 ID (PID) | 프로세스 고유 식별 번호 |
| 프로세스 상태 | 실행 중(Running), 대기(Waiting), 준비(Ready) 등 |
| 프로그램 카운터 | 다음에 실행할 명령어의 주소 |
| 레지스터 값 | 프로세스가 사용 중이던 CPU 레지스터 값 |
| 메모리 정보 | 할당된 메모리 주소 범위 |
| 자원 정보 | 열려 있는 파일, 사용 중인 I/O 장치 등 |

### 컨텍스트 스위칭 (Context Switching)

CPU가 실행 중인 프로세스를 전환할 때 현재 프로세스의 상태를 PCB에 저장하고, 다음 프로세스의 PCB를 불러와 실행을 재개하는 과정. 컨텍스트 스위칭이 너무 자주 발생하면 저장/복원 비용이 누적되어 성능이 저하된다.
