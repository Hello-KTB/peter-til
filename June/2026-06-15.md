# 1. 네트워크(Network)란?

> 데이터를 송수신하는 기기들 간의 연결을 통해 정보와 자원을 공유할 수 있게 하는 시스템
> 

네트워크는 단순히 선으로 연결된 상태가 아니라, 연결된 장치들이 실제로 데이터를 주고받을 수 있어야 한다.

## **왜 사용하는가?**

| 이유 | 설명 |
| --- | --- |
| 정보 공유 | 문서, 이미지, 영상, 데이터를 여러 장치가 주고받음 |
| 자원 공유 | 프린터, 파일 서버, 인터넷 회선을 여럿이 사용 |
| 원격 접속 | 멀리 있는 서버나 서비스에 접속 가능 |
| 협업 | 같은 시스템과 데이터를 기반으로 함께 작업 |
| 서비스 제공 | 웹 서버, API 서버 등이 사용자에게 서비스 제공 |

## **우편 비유**

| 네트워크 요소 | 우편 비유 | 역할 |
| --- | --- | --- |
| 패킷(Packet) | 편지(소포) | 데이터를 잘게 나눈 전달 단위 |
| IP 주소 | 도로명 주소 | 목적지 네트워크·장치 식별 |
| MAC 주소 | 집 호수 번호 | 같은 네트워크 안에서 특정 장치 식별 |
| 스위치 | 지역 우체국 | 같은 LAN 내 목적지 결정 |
| 라우터 | 물류센터 | 다른 네트워크로 가는 경로 결정 |
| 인터넷 | 전국·전세계 배송망 | 수많은 네트워크가 연결된 거대한 구조 |

## **개발자에게 네트워크가 중요한 이유**

```
API 서버 응답 없음 → 서버 문제? 포트 문제? 방화벽 문제?
DB 연결 실패       → DB 주소, 포트, 네트워크 접근 권한 확인 필요
배포 후 외부 접속 불가 → 보안 그룹, NAT, 로드밸런서 설정 확인 필요
```

내 프로그램이 다른 프로그램과 어떻게 연결되고, 어떻게 데이터를 주고받는지 이해하는 것이 핵심

# 2. 노드(Node)와 호스트(Host)

## 노드

> 네트워크 안에서 데이터를 보내거나 받고, 때로는 중간에서 전달하는 장치 또는 지점
> 
- PC, 스마트폰, 서버, 라우터, 스위치, 프린터 등
- 각 노드는 고유한 주소(MAC 주소 또는 IP 주소)를 가짐
- 단순 케이블은 노드가 아님 — 데이터를 직접 생성·수신·판단해야 노드

## 호스트

> 네트워크에 연결되어 서비스를 사용하거나 제공하는 최종 장치
> 

| 구분 | 설명 | 예시 |
| --- | --- | --- |
| 노드 | 데이터를 송수신하거나 전달하는 모든 장치·지점 | PC, 서버, 라우터, 스위치 |
| 호스트 | 서비스를 사용하거나 제공하는 최종 장치 | PC, 스마트폰, 웹 서버 |
- **노드 ⊇ 호스트** — 모든 호스트는 노드지만, 모든 노드가 호스트인 것은 아님
- 블록체인 검증 노드는 서비스가 없으므로 호스트가 아님
- 웹 서버는 노드이면서 호스트

# 3. LAN / WLAN / VLAN

## LAN (Local Area Network)

> 집, 사무실, 학교처럼 제한된 공간 안에서 여러 컴퓨터와 장치를 연결한 내부 네트워크
> 
- 외부 인터넷 연결 없이도 내부 장치끼리 통신 가능
- 같은 LAN 안의 노드들은 보통 동일한 사설 IP 대역 사용

### **LAN 내부 통신 vs 인터넷 통신**

| 통신 종류 | 예시 | 라우터 필요? |
| --- | --- | --- |
| LAN 내부 통신 | 내 PC → 같은 Wi-Fi의 프린터 | X |
| 인터넷 통신 | 내 PC → 구글 | O |

## WLAN (Wireless LAN)

> LAN 케이블 대신 무선 신호(Wi-Fi)로 연결한 네트워크
> 
- 구성 요소: 무선 NIC, AP(Access Point), SSID, WPA2/WPA3 인증
- 주의사항: 신호 간섭, 음영 지역, AP 과부하 → 실시간성이 필요한 서비스(IoT 등)에서 Retry 횟수와 ConnectionTimeout 설정이 중요

## VLAN (Virtual LAN)

> 하나의 물리적인 네트워크를 여러 개의 독립된 네트워크처럼 논리적으로 나누는 기술
> 

### **사용 이유**

| 이유 | 설명 |
| --- | --- |
| 보안 강화 | 서로 다른 VLAN 간 기본적으로 통신 불가 |
| 트래픽 감소 | 브로드캐스트 도메인 분리 |
| 관리 편의성 | 물리적 위치와 무관하게 논리적 그룹 구성 |

---

# 4. 네트워크 규모 비교

```
PAN < LAN < MAN < WAN
```

| 구분 | 범위 | 대표 예시 |
| --- | --- | --- |
| PAN | 개인 주변, 매우 짧은 거리 | 스마트폰-이어폰, 스마트워치 (Bluetooth, NFC) |
| LAN | 집, 사무실, 학교, 건물 | 가정 공유기, 사무실 내부망 |
| MAN | 캠퍼스, 도시, 여러 건물 | 대학 캠퍼스망, 도시 공공망 |
| WAN | 도시, 국가, 대륙 | 인터넷, 본사-해외 지사 연결 |

통신 규모가 넓어질수록 비용이 높아지고 속도가 느려진다. LAN으로 할 수 있는 통신을 위주로 설계하는 것이 좋다.

# 5. 네트워크 장비

데이터 흐름:

```
내 컴퓨터 → NIC → 스위치(or 허브) → 라우터 → 게이트웨이 → 인터넷 → 서버
```

## NIC (Network Interface Card)

> 컴퓨터가 네트워크에 연결되도록 해주는 하드웨어 구성 요소
> 
- 유선 NIC: 이더넷 케이블 — 안정적, 빠름
- 무선 NIC: Wi-Fi — 이동성, 노트북·스마트폰에 내장
- **MAC 주소**가 NIC에 하드웨어로 내장됨 (예: `00:1A:2B:3C:4D:5E`)
- 하나의 호스트가 여러 NIC를 가지면 여러 MAC 주소를 가짐 (유선용, 무선용, Bluetooth용 등)

## MAC 주소

> 네트워크 인터페이스의 물리적 식별자 — 같은 LAN 안에서 장치를 구분하는 주소
> 

### **IP 주소 vs MAC 주소**

| 구분 | MAC 주소 | IP 주소 |
| --- | --- | --- |
| 역할 | 물리적 식별자 | 논리적 위치 주소 |
| 사용 범위 | 같은 LAN 내부 | 네트워크 간 경로 결정 |
| 변경 가능성 | 기본적으로 고정 (스푸핑은 가능) | 환경에 따라 변경 가능 |
| 관련 계층 | L2 데이터 링크 | L3 네트워크 |
| 관련 장비 | 스위치, 브릿지, AP | 라우터, L3 스위치 |

**인터넷 서버의 MAC 주소는 내 컴퓨터가 모른다**

외부 서버로 패킷을 보낼 때는 서버의 MAC 주소가 아니라 **다음 홉인 공유기(게이트웨이)의 MAC 주소**를 목적지로 적는다. 최종 목적지는 IP 주소로만 지정한다.

**ARP (Address Resolution Protocol):** IP 주소에 해당하는 MAC 주소를 알아내는 프로토콜

## 허브(Hub)

> 연결된 모든 포트로 데이터를 무차별 전송하는 장치 (L1, 물리 계층)
> 
- MAC 주소, IP 주소 판단 없이 그냥 전부 뿌림
- 충돌(Collision) 발생 가능
- 현대에는 거의 사용 안 함 — 교육·개념 학습 목적

## 스위치(Switch)

> MAC 주소를 보고 필요한 장치에게만 데이터를 전달하는 장치 (L2, 데이터 링크 계층)
> 
- MAC 주소 테이블을 내부에 유지
- 목적지 MAC 주소를 모를 때: **Flooding** (모든 포트로 한 번 뿌린 후 응답으로 테이블 업데이트)
- VLAN 지원

### **허브 vs 스위치**

| 구분 | 허브 | 스위치 |
| --- | --- | --- |
| 전달 방식 | 모든 포트로 전달 | 목적지 포트로만 전달 |
| 보는 정보 | 신호 | MAC 주소 |
| 트래픽 효율 | 낮음 | 높음 |
| 보안성 | 낮음 | 높음 |

## 라우터(Router)

> IP 주소를 보고 패킷이 갈 다음 경로를 결정하는 장비 (L3, 네트워크 계층)
> 
- 스위치는 LAN 내부, 라우터는 **다른 네트워크로** 연결
- **라우팅 테이블**: 목적지 IP 대역 → 다음 홉 주소가 기록된 경로 안내표
- 최종 목적지까지 한 번에 보내는 게 아니라 **"다음 홉"** 을 결정

```
내 PC → 집 라우터 → 통신사 라우터 → 중간 라우터들 → 목적지 서버
```

### **라우팅 테이블이 만들어지는 방식**

| 방식 | 설명 |
| --- | --- |
| 직접 연결 경로 | 인터페이스에 IP 설정 시 자동 등록 |
| 정적 라우팅 | 관리자가 직접 경로 입력 |
| 동적 라우팅 | 라우터끼리 경로 정보 교환 (OSPF, BGP 등) |

## 게이트웨이(Gateway)

> 서로 다른 네트워크를 연결하고, 프로토콜 변환·필터링·IP 변환 등을 수행하는 장치 (L3 이상)
> 
- 내부망과 외부망의 출입구
- IP 주소 변환(NAT), 프로토콜 변환, 접근 제어 수행
- 가정용 공유기 = 라우터 + 스위치 + 게이트웨이 + NAT + 무선 AP가 하나로 합쳐진 장비

### **라우터 vs 게이트웨이**

| 구분 | 라우터 | 게이트웨이 |
| --- | --- | --- |
| 핵심 역할 | IP 기반 경로 선택 | 서로 다른 네트워크의 출입구 |
| 동작 계층 | 주로 L3 | L3 이상 (경우에 따라 L7까지) |

## 브릿지(Bridge)

> 두 개 이상의 LAN 세그먼트를 연결하고, MAC 주소 기준으로 필요한 트래픽만 전달하는 장비 (L2)
> 
- 스위치와 동작 원리 유사 (현대에는 스위치가 대체)
- Docker, Kubernetes 네트워크에서 **브릿지 네트워크** 방식으로 컨테이너 간 통신에 사용됨

## 리피터(Repeater)

> 약해진 네트워크 신호를 증폭하거나 재생해서 더 먼 거리까지 전달하는 장치 (L1, 물리 계층)
> 
- MAC 주소, IP 주소 판단 없이 신호만 복원·전달
- 현대 LAN에서는 대부분 스위치, AP, 메시 네트워크로 대체됨

# 6. OSI 7계층과 TCP/IP 계층 — 장비 대응

| 장비 | TCP/IP 계층 | OSI 계층 | 보는 정보 |
| --- | --- | --- | --- |
| 허브 | Network Access | L1 물리 | 전기 신호 |
| 브릿지/스위치 | Network Access | L2 데이터 링크 | MAC 주소 |
| 라우터 | Internet | L3 네트워크 | IP 주소 |
| 게이트웨이 | Application | L3 이상 | IP + 상위 계층 |

각 장비를 계층별로 나눈 이유

- 신호 전달·대상 선택·경로 결정·경계 처리 문제의 성격이 완전히 다르기 때문.
- 하나의 장비가 모두 처리하면 구조가 복잡해지고 장애 원인 파악이 어려워진다.

```
1. 물리적 연결이 되어 있는가?
2. IP 주소가 유효한가?
3. 목적지로 갈 수 있는가?   →  ping 8.8.8.8
4. 포트가 열려 있는가?      →  netstat -an | grep 8080
5. 애플리케이션이 응답하는가? →  curl https://localhost
```
