## 1. 동시성 (Concurrency)

> 작업이 물리적으로 동시에 실행되는 것이 아니라, CPU가 작업을 빠르게 전환(Switching)하여 마치 여러 작업이 동시에 실행되는 것처럼 보이게 하는 방식이다.
> 

### 특징

| 특징 | 설명 |
| --- | --- |
| 작업 간 전환 | 여러 작업을 빠르게 전환하며 실행 (실제 병렬 실행은 아님) |
| 자원 공유 | 여러 작업이 동일한 CPU와 메모리를 공유하며 동작 |
| 운영체제의 역할 | 스케줄링을 통해 작업 실행 순서를 조정하여 멀티태스킹을 구현 |
| 적용 분야 | I/O 중심 작업 (파일 입출력, 네트워크 처리 등)에서 효과적 |

### 왜 알아야 하는가?

많은 사용자 요청이 몰리는 백엔드 서버에서 자원을 적절히 관리하고, 병렬 작업 구조를 이해하고 최적화하기 위해 필수적이다.

- 효율적인 시스템 자원 활용
- 사용자 경험 개선

## 2. 스케줄러 (Scheduler)

> 운영체제의 핵심 구성 요소로, CPU와 같은 시스템 자원을 적절히 분배하기 위해 프로세스나 스레드의 실행 순서를 관리하는 역할을 한다.
> 

### 왜 필요한가?

**자원 독점**

- 무거운 연산 하나가 들어오면 CPU가 계속 이것만 처리한다.
- 예: 3초짜리 작업이 들어오면, 3초 동안 마우스 이동, 키보드 입력, 시계 갱신 등 다른 작업을 전혀 수행하지 못한다.

**기아 상태 (Starvation)**

- 우선순위가 높은 작업이 계속 들어오면 우선순위가 낮은 작업은 영원히 실행되지 못한다.
- 예: 우선순위 5번 작업(10ms)이 있어도, 더 높은 우선순위 작업들이 100ms, 200ms씩 계속 들어오면 실행 기회가 없다.

**시스템 낭비**

- CPU가 디스크 I/O를 기다리는 동안 아무것도 하지 않으면 낭비다.
- 대기 중인 다른 작업을 처리하면 효율이 높아진다.

### 스케줄러의 목표

| 목표 | 설명 |
| --- | --- |
| CPU 이용률 최대화 | CPU가 놀지 않도록 함 (CPU는 컴퓨터 자원 중 가장 비싼 자원) |
| 처리량 증가 | 단위 시간 내에 처리할 수 있는 작업의 양을 최대화 |
| 총 처리 시간 감소 | 작업 시작부터 완료까지의 시간 단축 |
| 대기 시간 최소화 | 프로세스가 기다리는 시간 최소화 |
| 응답 시간 최소화 | 사용자 요청에 빠르게 반응 |
| 공정성 확보 | 특정 프로세스 독점 방지 |

### 스케줄러의 기능

**작업 선택**

- 현재 실행 가능한 프로세스, 스레드 중에서 다음에 CPU를 할당할 대상을 고른다.
- 알고리즘: 라운드 로빈, 우선순위 기반 등

**자원 분배**

- 선택한 작업에 CPU 권한을 분배한다.
- 무한정 사용하게 두는 것이 아니라 타임 슬라이스(Time Slice) 단위로 부여한다.

**컨텍스트 스위칭 관리**

- 기존 작업에서 새 작업으로 전환할 때 기존 작업의 상태를 PCB에 저장하고, 새 작업의 PCB를 불러온다.

### 스케줄러의 종류

**장기 스케줄러**

- 역할: 보조기억장치(디스크, SSD)에 있는 프로그램 중에서 어떤 것을 RAM에 올릴지 결정
- 특징: 시스템에 한 번에 많은 프로세스가 올라오지 않도록 제어
- 현대 OS에서는 RAM 가격이 저렴해진 이후로 많이 사용되지 않는다.

**중기 스케줄러 (스왑 관리자)**

- 역할: 메모리가 부족할 때 활성화된 프로세스 일부를 중단시키고 디스크의 스왑 영역으로 옮겼다가, 여유가 생기면 다시 가져온다.
- 가상 메모리 구현과 연관되며 시스템 안정성을 높이는 역할을 한다.

**단기 스케줄러 (CPU 스케줄러)**

- 역할: 메모리에서 준비 상태에 있는 프로세스 중 CPU를 할당받을 프로세스를 결정
- 밀리초 단위로 빠르게 동작하며, 우리가 일반적으로 "스케줄링"이라 부를 때 이것을 가리킨다.

## 3. 스케줄링 (Scheduling)

> CPU와 같은 자원을 프로세스와 스레드들이 사용할 수 있도록 순서를 결정하는 운영체제의 정책이다.
> 

예: 크롬, VSCode, Discord가 동시에 실행될 때, CPU가 무한하지 않으므로 어떤 것을 언제, 얼마큼 실행할지에 대한 규칙이 스케줄링이다.

### 스케줄링의 레벨

```
Job Queue (작업 대기 큐)
    -> 이 중 누구를 올리자          (고수준 스케줄링)

Ready Queue (실행 준비 작업들의 대기 줄)
    -> 프로세스 선택
    -> CPU 할당                    (저수준 스케줄링)
```

| 레벨 | 역할 | 목표 |
| --- | --- | --- |
| 고수준 스케줄링 | 메모리에 올릴 프로세스 결정 | 시스템 전체 부하 조절 |
| 중간 스케줄링 | 메모리 부족 시 일부 프로세스를 잠시 내보냄 | 메모리 확보, 시스템 안정성 유지 |
| 저수준 스케줄링 | CPU를 누구에게 할당할지 결정 | 응답 시간 최소화, 처리량 극대화 |

### 스케줄링 알고리즘

**FCFS (First Come First Served)**

먼저 온 작업을 먼저 처리한다.

```
P1(30초) -> P2(1초) -> P3(3초) 순으로 처리
```

- 장점: 구현이 쉽다.
- 단점: 먼저 온 프로세스의 작업 시간이 길면 이후 모든 프로세스가 대기해야 한다 (Convoy Effect).

**SJF (Shortest Job First)**

가장 짧은 작업을 먼저 처리한다.

```
P1(30초), P2(3초), P3(1초) -> P3 -> P2 -> P1 순으로 처리
```

- 장점: 평균 대기 시간이 가장 짧고, 운영체제에서 가장 효율적인 알고리즘이다.
- 단점: 실행 시간을 사전에 예측하기 어렵고, 긴 작업이 계속 밀리는 기아 현상이 발생할 수 있다.

**SRTF (Shortest Remaining Time First)**

남은 실행 시간이 가장 짧은 프로세스를 실행한다. SJF의 선점형 버전이다.

- 선점형: CPU가 현재 프로세스를 실행 중이더라도, 더 짧은 작업이 들어오면 강제로 전환한다.

```
P1 실행 중 (남은 시간 10초)
P2 등장 (남은 시간 2초)
-> P1 중단 (9초 남음)
-> P2 실행
```

- 특징: 응답성이 좋아지지만, 컨텍스트 스위칭 비용이 높아진다.

**Priority**

우선순위가 높은 프로세스를 먼저 실행한다.

```
P1(우선순위 10), P2(우선순위 3), P3(우선순위 15)
-> P2 -> P1 -> P3 순으로 처리
```

- 장점: 중요한 작업을 먼저 처리할 수 있다.
- 단점: 우선순위가 낮은 작업에서 기아 상태가 발생할 수 있다.

**Round Robin**

모든 프로세스에게 동일한 CPU 시간(Time Slice)을 부여한다.

```
Time Slice = 3ms
P1(3ms) -> P2(3ms) -> P3(3ms) -> P1(3ms) -> ...
```

- 장점: 공정하고, 응답성이 준수하다.
- 단점: 타임 슬라이스 설정이 중요하다.
    - 너무 작으면: 컨텍스트 스위칭 오버헤드가 커진다.
    - 너무 크면: 응답성이 나빠진다 (사실상 FCFS와 다를 바 없다).

### 선점형 vs 비선점형

| 구분 | 설명 | 해당 알고리즘 |
| --- | --- | --- |
| 선점형 | 운영체제가 CPU 자원을 강제로 회수할 수 있다 | SRTF, Round Robin, Priority (선점형) |
| 비선점형 | 프로세스가 스스로 CPU를 반납할 때까지 기다린다 | FCFS, SJF |

Linux, Windows, Mac은 모두 선점형이다. 비선점형이면 프로세스가 정상 종료되지 않을 경우 자원을 무한히 점유하게 되는 문제가 생기기 때문이다.

### Multilevel Queue

프로세스를 그룹별로 나누어 관리하고, 각 그룹마다 다른 알고리즘을 적용한다.

```
실시간 작업      -> 우선순위 기반
일반 사용자 작업 -> 라운드 로빈
배치 작업        -> FCFS
```

현대 운영체제는 여러 알고리즘을 혼합해서 사용한다.

- Linux: 우선순위 + 라운드 로빈 + Fair 스케줄링 + 로드 밸런싱
- Windows: 동적 우선순위 + 라운드 로빈

### 현업에서의 활용

**백엔드 개발자**

- 일반적으로 스케줄링을 직접 제어하지 않는다. 운영체제가 결정한다.
- 그러나 성능 최적화 및 트러블 슈팅 시에 이해가 필요하다.
    - CPU 사용량은 100%가 아닌데 처리 속도가 나오지 않는 경우: 컨텍스트 스위칭 과다 또는 스레드 수 과다일 가능성이 높다.

**인프라 엔지니어**

- Linux에서 일부 설정 가능하다.
    - `nice`, `renice`: 우선순위 조정
    - CPU Affinity: 특정 프로세스를 특정 CPU에 고정
    - 쿠버네티스: CPU 할당 정책 설정

## 4. 병렬성 (Parallelism)

> 여러 CPU 코어 또는 프로세서를 사용하여 여러 작업을 실제로 동시에 실행하는 기술이다.
> 

### 동시성과 병렬성의 차이

| 구분 | 설명 |
| --- | --- |
| 동시성 | 1개의 코어가 작업 시간을 쪼개서 여러 작업을 동시에 처리하는 것처럼 보이게 함 |
| 병렬성 | 여러 코어에서 여러 작업을 실제로 동시에 실행 |

동시성은 "동시에 처리하는 것처럼 보이는 것", 병렬성은 "실제로 동시에 실행되는 것"이다.

### 왜 사용하는가?

CPU 코어가 8개인데 1개만 사용하면 나머지 7개는 놀고 있다. 병렬성을 활용하면 여러 코어가 작업을 나누어 처리하여 시스템 성능을 극대화할 수 있다.

| 이유 | 설명 |
| --- | --- |
| 성능 향상 | 여러 작업을 동시에 처리하여 실행 시간 단축 |
| CPU 활용도 증가 | 여러 코어를 모두 활용 |
| 실시간 처리 | 게임, 스트리밍, 영상 처리 등에서 빠른 응답 제공 |
| 대규모 데이터 처리 | 머신러닝, 빅데이터 분석 속도 향상 |

### 병렬 동작 방식

1. **작업 분할**: 하나의 큰 작업을 여러 개로 나눈다.
    - 예: 이미지 100만 장 분석 -> 25만 장씩 4개로 분할
2. **코어 할당**: 분할된 작업을 각 CPU 코어에 할당한다.
    - Core 1 -> 작업 A / Core 2 -> 작업 B / Core 3 -> 작업 C / Core 4 -> 작업 D
3. **병렬 실행**: 각 코어가 독립적으로 병렬 실행한다.
4. **결과 통합**: 각 코어의 결과를 하나로 합친다.
5. **오류 처리**: 특정 코어에서 오류 발생 시 처리한다.

### 병렬성의 특징

| 특징 | 설명 |
| --- | --- |
| 하드웨어 의존적 | 멀티코어 CPU가 있어야 가능 |
| 작업의 독립성 | 각 작업이 서로 간섭 없이 독립적으로 실행되어야 함 |
| 계산 중심 | 대규모 데이터 처리, 연산 중심 작업에 최적화 |
| 성능 향상 | 코어 수가 많을수록 더 많은 작업을 동시에 처리 가능 |

### 실무 활용 사례

- 게임 (물리 연산, 렌더링 등 병렬 처리)
- 영상 작업 (AI Upscaler: 저화질 영상을 AI로 고화질로 변환)
- 인공지능 학습 (대규모 행렬 연산 병렬 처리)
- 빅데이터 분석

### 실무적인 주의사항

**병렬성이 항상 정답은 아니다**

- 작업 분할 비용 + 스레드 생성 비용 + 결과 병합 비용 = X
- 싱글 코어 동시성 비용 = Y
- X < Y일 때만 병렬성을 사용하는 것이 유리하다.
- 작은 작업에 병렬성을 적용하면 오히려 느려질 수 있다.

**공유 자원 주의 (Race Condition)**

- 여러 코어가 동일한 자원에 동시에 접근할 때 Race Condition이 발생할 수 있다.
- 공유 자원 접근 시 동기화 처리가 필요하다.

**물리적인 제한**

- 코어 수 이상의 병렬 처리는 불가능하다.
- AWS 등 클라우드 인프라 사용 시 인스턴스의 CPU 코어 수를 반드시 확인해야 한다.
- 예: 8코어라면 동시 병렬 실행은 최대 8개까지만 가능하다.
