# 1주차 과제 회고

---

## 1. 과제 내용

### 진행한 과제

- 과제 1 : 클래스 다이어그램 작성
- 과제 2 : 클래스 다이어그램에 따른 CLI 프로그램 제작

### 구현한 기능

- 기능 1 : 각 운동별 정보 입력에 따른 운동 시간 및 소모 칼로리, 세부 스탯 출력
- 기능 2 : 잘못 입력 시 오류 메시지 출력
- 기능 3 : Running과 Football의 세부 운동 스탯 분리 출력

---

## 2. 과제 설명

### 과제 목적

- 객체지향의 개념을 이해했는지 확인 (특히 상속)
- AI 도움 없이 스스로 구현하며 문제 해결 능력 기르기

### 설계

- Sport를 부모 클래스로 설계하고, 스포츠의 공통 특징인 운동 시간과 소모 칼로리를 속성으로 설정하였다.
- 각 속성의 get(), set() 메서드와 현재 운동 정보를 출력하는 메서드를 구현하였다.
- Sport의 자식 클래스로 Running과 Football을 설계하였다.
    - Running은 Sport의 공통 속성과 메서드를 상속받으면서, Running만의 특징을 추가로 가지기 때문에 자식 클래스로 구성하였다.
    - Football 또한 공통 기능을 공유하면서 종목별 특징을 분리하기 위해 자식 클래스로 설계하였다.

### 처음 구현했던 방식

- 처음에는 각 자식 클래스마다 운동 메서드를 따로 구현
    - Running → run()
    - Football → play()
    - Fitness → exercise()

- 부모 클래스의 속성
    - 운동 시간
    - 소모 칼로리
    - 심박수

- 운동이 끝날 때마다 부모 클래스의 총 운동 시간과 총 칼로리를 하나로 누적 관리하려고 설계

### 리팩토링

- 각 운동 클래스마다 운동 메서드가 따로 존재할 필요가 없다고 판단
- 부모클래스에 exercise() 메서드를 선언하고, 자식 클래스에서 override하는 방식으로 수정
- heartbeat 속성을 제거하고 weight 속성 추가
    - 조사 결과 칼로리 계산에는 심박수보다 체중이 더 큰 영향을 미침
- 속성을 private으로 설정하고 getter/setter 추가

## 3. 문제 발생

### 문제 상황 1 : 중복되는 속성과 메서드 발생

#### 원인 분석

- 처음에는 각 운동 클래스마다 운동 메서드를 따로 구현함
- 하지만 실제 구현 과정에서:
    - 운동 실행
    - 상태 출력
    - 시간 및 칼로리 갱신

등이 대부분 공통 기능이라는 점 발견

- 예상했던 것보다 코드 중복이 많아졌고, OOP개념으로 효율적이지 않다고 판단

---

### 문제 상황 2 : 부모 클래스 속성 값 공유 실패

#### 원인 분석

- 원래는 운동이 진행될 때마다 부모 클래스의 총 운동 시간과 총 칼로리를 누적 관리하려고 함
- 하지만 자식 객체를 생성할 때마다 부모 객체 또한 각각 생성된다는 점을 코드 작성 과정에서 다시금 떠올림
- 내가 생각했던 구조:
    - 하나의 부모 객체를 모든 자식 객체가 공유
- 실제 코드 구조:
    - 자식 객체마다 각각의 부모 객체 생성

- 즉, 객체 흐름 자체를 잘못 이해하고 있었음

---

## 4. 해결 과정

### 해결 방법 1

- 부모 클래스에 exercise() 메서드를 선언하고 자식 클래스에서 override하도록 수정
- 공통 기능은 부모 클래스에서 관리하고, 운동별 세부 동작만 자식 클래스에서 구현
- 객체지향의 상속과 오버라이딩 개념을 적용

### 해결 방법 2

- 기존에는 모든 운동 결과를 하나로 누적 출력하려고 함
- 하지만 객체 생성 구조를 다시 이해한 후, 운동 선택 시 해당 운동 결과만 출력하도록 CLI 구조 변경

| 수정 전 | 수정 후 | 개선 이유 |
|---|---|---|
| 전체 운동 결과 통합 관리 | 운동별 개별 결과 출력 | 객체 흐름에 맞는 구조 |
| 각 클래스별 개별 운동 메서드 | 부모 클래스 exercise() 공통화 | 중복 제거 |

### 최종 결과

- 운동 선택 시:
    - 운동 시간
    - 소모 칼로리
    - 운동별 세부 스탯

이 출력되는 CLI 프로그램 완성

- 상속 구조, 객체 흐름, 캡슐화, 공통 기능 분리를 통한 OOP 개념 재확인

## 5. 느낀 점

### 이번 과제를 통해 배운 점

- 코딩을 통해서 자연스럽게 객체지향의 개념들을 익히고 있는지 스스로 확인할 수 있었다.
- 코딩을 하면서 처음 계획의 부족한 점들을 확인할 수 있었고, 그에 따라 리팩토링을 할 수 있었다. 이 과정을 통해서 자신의 코드에 의문을 가지고 지속적으로 질문하면서 코드의 효율성을 높일 수 있었다고 생각한다.
- 초안 완성 후에 객체 생성 과정과 부모클래스와 자식클래스 관계를 코드 흐름 기준으로 이해할 수 있었다.

### 아쉬웠던 점

- 과정 중에 GPT 사용이 금지이지만, 클래스 다이어그램 설계 과정에서 답답함에 못 이겨 gpt를 통해 의문점을 해결했다.
    - 결국 코드를 통해 다이어그램을 수정하면서 온전히 나만의 결과물이 됐지만, 과정 중에 ai 사용하지 않기를 지키지 않았다는 점이 매우 아쉬움
- 원래 계획했던 “총 운동 시간 및 총 칼로리 통합 관리” 기능을 구현하지 못하였다. 이 부분은 내가 객체지향의 개념을 숙지하지 않은 상태로 설계해서 발생했다.
- getter/setter와 접근 제어자의 필요성을 아직 완전히 체감하지는 못하였다.
