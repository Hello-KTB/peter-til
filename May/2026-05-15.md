### 주제 1: 객체지향 기초

객체지향 프로그래밍(OOP)은 프로그램을 객체들의 상호작용으로 바라보는 프로그래밍 방식이다.

- 절차지향
    - 코드가 순서대로 실행되는 구조
    - 규모가 커질수록 유지보수가 어려움
- 객체지향
    - 객체 단위로 역할을 나누어 설계
    - 재사용성과 유지보수성이 높음

객체지향의 핵심 특징

- 캡슐화
    - 데이터와 메서드를 묶고 내부 구현 숨김
- 추상화
    - 공통된 특징만 추출하여 설계
- 상속
    - 부모 클래스의 기능 재사용
- 다형성
    - 하나의 객체가 여러 형태로 동작 가능

인터페이스는 객체가 구현해야 할 기능의 규칙을 정의하며, 상속은 부모의 기능을 물려받는 개념이라는 차이점이 존재한다.

### 주제 2: 제네릭과 컬렉션

제네릭(Generic)은 타입을 미리 지정하지 않고 나중에 결정할 수 있도록 하는 문법이다.

- 컴파일 시점 타입 검사 가능
- 형변환 최소화
- 코드 재사용성 증가

컬렉션(Collection)은 여러 데이터를 쉽게 관리하기 위한 자료구조이다.

- List
    - 순서 보장
    - 중복 허용
- Set
    - 중복 허용 안 함
- Map
    - Key-Value 형태 저장
    - 빠른 검색 가능

### 주제 3: 멀티스레드와 동시성

스레드는 프로그램 내부의 실행 흐름이며, 멀티스레드는 여러 실행 흐름을 동시에 또는 번갈아 처리하는 구조이다.

멀티스레드를 사용하는 이유

- 응답성 유지
- 백그라운드 작업 처리
- 자원 효율 향상
- 대용량 작업 처리 가능

Runnable은 실행할 작업을 정의하는 인터페이스이며, Thread와 역할을 분리하기 위해 사용한다.

ExecutorService는 스레드 풀을 관리하여 성능과 안정성을 높여준다.

동시성 문제 해결을 위해 synchronized와 Lock을 사용하고, 공유 자원 접근을 제한하여 데이터 충돌을 방지할 수 있다.

## 오늘의 회고

객체지향 개념은 공부해도 완벽한 그림이 머릿속에서 그려지진 않는다. 이것도 추상화인가 싶다.

제네릭과 컬렉션은 사용하기만 해봤지, 자세하게 공부하진 않았다. 간단하게 공부하고 넘어간 파트지만 그래도 유익한 수업이었다.

마지막으로 멀티스레드와 동시성이 오늘 배운 내용 중 가장 중요했고 또 분량이 많았다. 중요한데 분량 또한 많아서 복습하는데 시간이 꽤 걸릴듯 하지만, 무조건 보고 넘어가야 하는 내용이다.

cli과제를 진행하면서 초반에 설계했던 클래스 다이어그램의 오류들을 발견할 수 있었고, 진행하면 할수록 중복되는 것들이 보이면서 코드를 어떻게 하면 효율적으로 짤 수 있는지에 대해서 고민하는 나를 발견할 수 있었다. 그리고 무엇보다 상속의 개념 오인해서 실수가 발생했는데, ai 도움 없이 개념을 떠올리고 문제 해결까지 해서 개인적으로 뿌듯했다. Ai의 도움을 받지 않으니 확실히 시간이 오래 걸리지만, 그만큼 쏟는 시간이 많아지면서 고민도 더 많이 하게 됐다.
